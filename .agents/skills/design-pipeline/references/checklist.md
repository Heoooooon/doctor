# 실행·인계 체크리스트

[절차로 돌아가기](../SKILL.md) | [평가 루브릭](rubric.md) | [위임 프롬프트](prompts.md)

이 양식은 검수 실행 기록이 아니다. 대상 작업의 승인된 산출물 위치로 복사하고 `<...>`를 실제 값으로 채운다. 체크는 증거가 있을 때만 한다. 상태는 `미시작 / 진행 / 완료 / 실패 / 미검증 / 소유자 대기 / N/A(이유)` 중 하나로 쓴다.

## 1. 범위·입력·역할

- [ ] 요청 의도·대상 독자·페이지/섹션 범위·허용 파일·제외 작업을 기록했다.
- [ ] 시작 시 사용자 변경과 worktree 기준 상태를 기록하고 보존했다.
- [ ] AGENTS와 브랜드/디자인/SEO/의료 문서, 기존 취향·방향·리뷰·DESIGN·연구 README를 읽었다.
- [ ] 문서 충돌, 새로 필요한 사실, 재사용 가능한 완료 연구를 구분했다.
- [ ] Aside 단일 드라이버와 이미지 판독 담당을 지정했다. 개인 프로필 초기화와 운영 제출은 금지했다.

```text
대상 저장소/worktree: <실제 위치>
허용 파일 / 보존할 사용자 변경: <목록>
입력 경로·버전 / 읽지 못한 자료: <목록과 이유>
요청·방향 승인 출처 / 허용 범위: <실제 지시 위치 또는 승인 대기>
오케스트레이터 / 이미지 리뷰어 R1·R2: <실제 담당과 판독 가능 여부>
브라우저 표면 / 승인된 격리 환경: <실제 도구·프로필 범위, 비밀값 제외>
```

## 2. 취향부터 계약까지

- [ ] 취향의 인용·해석·전언·미확인을 분리하고 정보·사진·읽는 흐름·운영 요구를 연결했다.
- [ ] 레퍼런스의 URL·확인일·실제 이미지·가져올/버릴 원리·권리 상태를 기록했다.
- [ ] A/B/C가 같은 내용의 서로 다른 방향이며 모든 섹션의 읽을 수 있는 모바일/데스크톱 원본이 있다.
- [ ] 생성 도구 성공/403/대체 상태를 정확히 기록했다. HTML 렌더를 모델 생성물로 표시하지 않았다.
- [ ] R1/R2가 서로의 결과 없이 실제 이미지를 열고 섹션별 6축 점수를 냈다.
- [ ] 선택/혼합 후보는 각 리뷰어의 모든 섹션 평균 >=4이며 잘림·CJK·접근성·차단 결함이 없다.
- [ ] 추천과 소유자 승인 범위를 분리했다. 명시적 진행 지시 없이 UI 구현하지 않았다.
- [ ] DESIGN에 기하·토큰·카피·자산·상태·반응형·접근성·CTA·차이·미확정·완료 조건이 있다.

| 산출물 역할 | 대상 프로젝트의 실제 경로 | 버전·상태·증거 |
|---|---|---|
| 취향 | `<design/taste-profile.md 또는 실제 경로>` | `<출처 구간과 상태>` |
| 레퍼런스 | `<design/references/README.md>` | `<URL/캡처 목록>` |
| 시안/생성 기록 | `<design/concepts/MANIFEST.md>` | `<A/B/C 전체 파일, 생성/HTML 구분>` |
| 독립 리뷰 | `<design/reviews/concepts-r1.md, concepts-r2.md>` | `<열람 목록·점수·차단>` |
| 방향 | `<design/DIRECTION.md>` | `<추천/실제 승인 출처/범위>` |
| 계약 | `<DESIGN.md>` | `<적용 버전, 미확정>` |

## 3. 구현·명령 검증

- [ ] 실제 DOM·텍스트·링크·컨트롤로 구현했고 정적 제품 캡처와 동작 UI를 구분했다.
- [ ] 동작 변경은 실제 seam의 RED 실패 원인·최소 수정·GREEN 결과를 남겼다.
- [ ] async는 정확한 이벤트 사전 구독과 제한 시간을 사용한다. 고정 sleep/지연 폴링·통합을 없애는 mock이 없다.
- [ ] 시각·카피만 바뀌면 실제 화면을 검수하고 원문을 고정하는 테스트를 추가하지 않았다.
- [ ] 변경 파일 진단을 빌드 전에 확인했고 관련 테스트·빌드·실제 실행 명령 결과를 남겼다.
- [ ] 안전 설정·사용자 변경 보존을 확인했다. 사전 실패와 이번 변경의 실패를 구분했다.

작업 크기에 맞춰 검증한다. 단일 파일 비동작 변경은 파일 진단, 단일 영역 동작 변경은 진단·관련 테스트·실제 entry point 실행, 다중 파일/횡단 구현은 전체 변경 파일 진단·관련 테스트·빌드·실제 표면 검수다. Markdown 진단 도구가 없으면 그 한계를 쓰고 링크/frontmatter 구조 검사를 기록한다. 문서 패키지에 앱 테스트를 억지로 추가하지 않는다.

| 검증 | 채울 실제 명령/도구 호출 | 실행 결과·로그 경로 |
|---|---|---|
| 기준/최종 상태 | `git status --short`, `git diff --stat`, `git worktree list` | `<전후 결과>` |
| diff 품질 | `git diff --check` 및 신규 파일 확인 | `<결과>` |
| 파일 진단 | `<변경 파일별 LSP/저장소 lint 호출>` | `<결과 또는 도구 미지원>` |
| RED/GREEN | `<package.json/저장소 안내에서 확인한 관련 test 명령>` | `<각 결과·실제 seam, N/A 이유>` |
| 빌드 | `<실제 build script 명령>` | `<종료 코드·로그>` |
| 실제 실행 | `<실제 dev/preview/demo 명령>` | `<URL·모드·후보 버전>` |
| 최종 후보 | `git rev-parse HEAD`, `git status --short` | `<리뷰 전후 일치 증거>` |

명령 예시는 실행 사실이 아니다. 설치된 도구·저장소 스크립트를 읽고 채운다. 명령 실패를 생략하거나 재시도 운으로 GREEN을 만들지 않는다.

## 4. 실제 브라우저·이미지 증거

- [ ] 계약의 전체 섹션과 헤더/푸터, breakpoint 경계·좁은 화면·모바일/태블릿/데스크톱을 빠짐없이 등록했다.
- [ ] 200% 확대·400% reflow, 키보드/포커스, reduced motion, 폰트·이미지 실패를 확인했다.
- [ ] 모든 해당 상태와 실제 CTA·앵커·다운로드·안전한 폼 동작을 재현했다. 없는 상태는 이유 있는 N/A다.
- [ ] 로드·상태 신호 후 전체 페이지와 읽을 수 있는 섹션 캡처를 만들었다. 캡처만으로 픽셀 검수라고 하지 않았다.
- [ ] 실제 DOM 캡처도 R1/R2가 독립 평가했고 양쪽 모든 섹션이 게이트를 충족했다.
- [ ] 시각/카피 결함과 수정 전후 증거가 연결된다. 변경 섹션·이웃·영향 상태를 다시 확인했다.

`design/evidence/<run-id>/manifest.md` 예시 항목:

```text
후보 버전 / 실제 실행 명령 / 빌드 모드 / 서버 URL: <채움>
전체 섹션 목록 / 전체 viewport·상태 목록: <누락 판단용 원장>
캡처 시점 / CSS viewport / DPR / 이미지 원본 치수: <채움>
브라우저 드라이버 / 픽셀 관찰자 / 판독 불가 범위: <채움>
로딩 완료 신호 / 상태 재현 동작 / 콘솔·네트워크 로그: <채움>
전체 캡처 / 개별 캡처 / R1·R2 실제 DOM 리뷰: <실제 경로>
```

| route·섹션 | viewport·상태 | 재현 동작/정확한 완료 신호 | 캡처·동작 증거 | R1/R2 평균 | 차단·수정·재검수 |
|---|---|---|---|---|---|
| `<목록의 각 행>` | `<실측 또는 N/A 이유>` | `<실제 절차>` | `<경로>` | `<개별 점수>` | `<결함 ID 또는 확인 결과>` |

## 5. 최종 HEAD·인계·공개 분리

- [ ] 코드·자산이 동결되고 검증한 트리가 실제 후보 HEAD와 일치한다. 미커밋 변경을 HEAD 검사로 포장하지 않았다.
- [ ] 커밋이 필요하면 별도 사용자 권한을 확인했다. 없으면 후보 확정 대기로 남겼다.
- [ ] 새 컨텍스트 ultrabrain 1명이 정확한 HEAD·diff·계약·원본 증거를 검토했고 전후 HEAD가 같다.
- [ ] 최종 보고서는 후보 트리 밖에 기록했다. 후보 변경 시 이전 판정을 만료시켰다.
- [ ] 최종 차단 항목이 없으며 미검증·소유자 대기를 완료로 표시하지 않았다.
- [ ] 병합은 별도 권한과 동일 후보 확인 후에만 한다. 통합 결과가 달라지면 재검증한다.
- [ ] 공개 호스트·사업 정보·문의 채널·권리·운영 책임과 출시 승인을 별도로 확인했다.
- [ ] noindex·인증·동의·의료/개인정보 보호를 점수 때문에 제거하지 않았다.
- [ ] 검색/예약 성과는 관측 자료와 기간이 있을 때만 보고하며 클릭·접수·예약 확정을 분리했다.

```text
인계 결과
- 구현·로컬 noindex 품질: <완료/실패/미검증 + 실제 검증 증거>
- 독립 이미지 게이트: <R1/R2 전 섹션 결과와 미해결 목록>
- 최종 ultrabrain 리뷰: <정확한 HEAD, 보고서 경로, 실제 판정 또는 대기>
- 병합: <권한 출처·범위 / 미승인; 실행했다면 실제 결과>
- 공개 출시: <소유자 승인/대기, 필요한 입력과 담당>
- 실제 SEO/예약 성과: <관측 자료·기간 또는 미측정>
- 남은 차단·미검증·사전 실패: <항목별 이유와 담당>
```
