# 섹션별 디자인 루브릭

[절차로 돌아가기](../SKILL.md) | [기록 체크리스트](checklist.md)

## 평가 단위와 6축

각 리뷰어는 각 방향/구현 버전의 **모든 섹션**에 아래 여섯 정수 점수(1~5)를 준다. 헤더·푸터·공용 인터랙션도 별도 행으로 평가한다. 섹션이 여러 viewport/상태에 걸치면 각각 관찰하고 축별 최저 점수를 섹션 대표점수로 쓴다. 좋은 데스크톱이 나쁜 모바일을 상쇄하지 않는다.

| 축 | 판단 질문 | 높은 점수의 증거 / 감점 예 |
|---|---|---|
| 정보우선성 | 누구에게 무엇을 제공하고 다음 행동이 무엇인지 바로 읽히는가? | 실제 질문에 답하는 정보·CTA / 장식 선행, 반복 카피, 연락 행동 분산 |
| 실사진감 | 실제 사진·제품 화면이 주장에 맞는 근거로 작동하는가? | 출처 있는 자료, 읽을 수 있는 화면, 적절한 크롭 / 무관한 분위기 사진, 가짜 프리셋, 근거 가림 |
| 타이포 위계 | 제목·요약·본문·보조 정보와 CJK 읽기 흐름이 명료한가? | 크기·행간·폭·대비의 목적 있는 차이 / 고아 음절, 단어 분절, 작은 옅은 캡션 |
| 여백·밀도 | 내용의 중요도와 양에 맞는 공간인가? | 묶음과 시선 흐름, 읽는 폭 / 넓은 공백 속 좁은 다열 본문, 불필요한 긴 페이지 |
| 신뢰감 | 과장 없이 실제 제공물·진료 철학을 설득하는가? | 사실·권리·개인차 안내와 차분한 카피 / 자격 오기, 치료·검색 결과 보장, 미확정 신원 위장 |
| 구현가능성 | 반응형·접근성·실제 기능·자산·운영으로 유지할 수 있는가? | 실제 DOM과 상태·갱신 가능 자료 / 고정 보드만 성립, 가짜 버튼, 확보 불가능 자산 |

사진이 필요 없는 질문·절차 섹션의 실사진감은 장식 이미지를 억지로 요구하지 않는다. 설명의 근거 적합성과 불필요한 이미지의 절제를 평가해 이유를 쓴다. 이미지가 보여주는 구조적 구현가능성은 실제 기능·권리·반응형 검증이 아니므로 검증 범위를 별도 표시한다.

## 점수 앵커

- **1**: 목적 전달이 실패하거나 사용할 수 없다.
- **2**: 주요 시각·정보 결함으로 구조적 수정이 필요하다.
- **3**: 이해는 되지만 시안/제안서 수준이다. 상업 품질로 내보내기에는 편집·사진·밀도 교정이 필요하다.
- **4**: 대상 독자가 읽고 판단할 수 있는 상업 품질이다. 의도와 근거가 명료하며 필수 결함이 없다.
- **5**: 근거·타이포·밀도·행동이 특별히 잘 통합된 완성품이다. 구체적인 화면 관찰로 이유를 설명할 수 있다.

## 통과 규칙

리뷰어 r, 섹션 s에 대해 `section_average(r,s) = (6개 축 점수의 합) / 6`이다. **R1과 R2가 각각 모든 섹션에서 평균 >= 4.0/5**여야 한다. 소수점 표시 반올림으로 4 미만을 통과시키지 않는다. 리뷰어 간 평균·방향 전체 평균·페이지 평균은 비교용일 뿐 게이트가 아니다. 미열람 또는 미채점 섹션은 통과가 아니라 미검증이다.

평균과 무관하게 다음 미해결 항목이 하나라도 있으면 HOLD:

- 텍스트·사진 핵심·컨트롤·포커스 잘림, 겹침, 내용 손실, 의도치 않은 가로 넘침.
- CJK 고아 음절/조사, 단어 중간의 부자연스러운 분절, 의미를 깨는 강제 줄바꿈.
- 접근성 결함: 계약 미달 글자 크기·대비·터치 영역, 키보드 차단, 가려진 초점, 잘못된 의미/레이블, 확대 시 정보 손실.
- 작동하지 않는 CTA·누락 필수 자산, 가짜 생성물·기능·승인, 권리/개인정보/의료광고 차단 이슈, 근거 없는 치료·검색 성과 보장.
- 이미지 판독 실패, 필수 viewport/상태 누락, 실제 DOM 검수 대신 정적 보드만 제출, 검수 대상 버전 불일치.

방향 비교에서 탈락안은 낮은 점수를 유지한다. 선택안 또는 혼합안의 실패 섹션만 교정하고 관련 영향 범위를 다시 평가한다. 두 사람의 원문을 합쳐 덮어쓰지 않는다. 불일치는 같은 이미지·viewport·상태를 대조하고 관찰 근거로 해결하며 숫자를 협상해 통과시키지 않는다.

## 리뷰 출력 양식

아래 `<...>`는 실제 확인 후 채운다. 미확인은 `미검증`으로 둔다.

```text
리뷰어/실제 이미지 판독 가능 여부: <ID, 가능/불가>
후보 버전/단계: <artifact revision 또는 HEAD, 시안/실제 DOM>
입력 manifest: <경로>; 실제 열람 파일: <전체 목록>; 실패: <파일과 이유>
다른 리뷰어 출력 사전 열람: <없음 또는 독립성 훼손 내용>
```

| 방향/버전 | 섹션 | viewport·상태·이미지 | 정보 | 사진 | 타입 | 밀도 | 신뢰 | 구현 | 평균 | 차단/미검증 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| `<채움>` | `<전체 목록에서 1행>` | `<실제 경로>` | `<1~5>` | `<1~5>` | `<1~5>` | `<1~5>` | `<1~5>` | `<1~5>` | `<계산>` | `<명시>` |

각 결함: `<ID / 파일 / 섹션 / viewport·상태 / 위치 또는 이미지 좌표 / 관찰 / 사용자 영향 / 정확한 수정 제안 / 재검수 증거>`.

마지막에 가장 강한·약한 섹션과 이유, 추천 방향 1개, 상업 품질에 부족한 점, 코드/권리/운영 등 미검증 범위, `PASS/HOLD/미검증` 판정을 기록한다. PASS는 실제 게이트 충족 시에만 작성한다.
