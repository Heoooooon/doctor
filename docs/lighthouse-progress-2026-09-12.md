# 홈페이지 Lighthouse 개선 진행 기록

## 상태

**모바일·데스크톱 네 항목 모두 100점이라는 목표는 아직 미달이다.**
2026-09-12 사용자 승인으로 백업 후 운영 배포까지 완료했다. 코드 커밋·푸시는 하지 않았다.
기존에 운영 배포한 SEO·칼럼 인증 수정과 섞여 있는 작업본이므로 전체 diff를 이번 성능 변경으로 설명하지 않는다.

사용자가 Lighthouse 측정에 한해 개인 계정과 분리한 임시 Chrome 프로필 사용을 승인했다.
실제 Google Chrome 152.0.7977.83, Lighthouse 13.4.1 Node API, Puppeteer Core 25.5.0을 사용했다.
headless-shell·감사 항목 제외·요청 차단·인트로/팝업 우회 없이 기본 모바일/데스크톱 시뮬레이션을 실행했다.
각 실행 후 임시 브라우저와 프로필을 정리했다.

| 변경 전 로컬 프로덕션 데스크톱 | 80 | 97 | 100 | 92 |

운영과 로컬의 응답 속도·호스트·네트워크 차이를 코드 개선 효과로 계산하지 않는다.
각 초기 측정은 1회이며 반복 중앙값이 아니다.

## 구현

- 히어로 정지 이미지 4개: 데스크톱 합계 25,342,948 → 300,358바이트.
  24,672,067바이트 PNG는 117,522바이트 WebP로 교체. 원본·종횡비 보존.
- 첫 영상: 547,896 → 123,312바이트. H.264, 1280×720, 24fps, 62프레임, 2.583333초 유지.
  전체 프레임 SSIM 0.990008. 소리 없는 배경 영상의 비디오 트랙만 제공.
- 히어로 현재·이전·다음 정지 이미지 위주로 source 연결. 숨겨진 기기별 미디어 중복층 제거.
- 수면치료 영상은 화면 접근 시 로드, 진입 시 재생, 이탈 시 일시정지.
- 화면 아래 의료진 사진의 강제 preload 제거, 헤더 로고의 sizes 명시.
- Pretendard를 동일 글리프의 가변 서브셋으로 제공하고 외부 CSS 요청 제거.
  홈 우선 폰트 101,440바이트, 461 codepoints. 범위 밖 문자는 상류 92개 서브셋으로 폴백.
- 인트로 Paperlogy는 필요한 25문자 서브셋: 164,128 → 2,784바이트.
  라이선스와 생성 스크립트 포함.
- 홈에서 사용하지 않는 SmoothScroll/GSAP는 조건부 동적 import로 분리.
- 닫힌 모바일 메뉴의 불필요한 경로 prefetch 차단, inert 적용, 닫을 때 포커스 복원.
- 팝업 표시 점의 실제 터치 영역 44×44px. 이미지 사전 로딩 시 실제 크기를 얻어 렌더 시 예약.
- 팝업 이동·확대 모션은 유지하고 이미지에만 페이드 적용해 버튼 글자 대비 유지.
- 푸터·CTA 대비와 임플란트 링크의 설명 문구 개선.
- 네이버 블로그 유입 카드, 상담, 팝업, 여섯 슬라이드, 기존 진료 내용 유지.

## 아직 해결하지 않은 100점 조건

현재 초기 폰트·네트워크 경쟁은 모바일 시뮬레이션 LCP에 남아 있다.
인트로 3초·페이드 0.8초·자동 팝업이 모두 담긴 이전 추적에서는 표시 순서 자체가
Speed Index 변동에 크게 기여했다. 현재 반복 측정 일부는 그 전환 전에 끝나므로,
이 기록을 전체 진입 경험의 안정적인 100점 증거로 사용할 수 없다.

기존 진입 방식은 유지했다. 앞으로 인트로를 비차단 방식으로 바꾸거나 공지를 작은 배너/사용자 선택형으로 바꾸는 것은
보이는 동작에 대한 결정이며 소유자 확인이 필요하다. 그런 변경 없이 남은 코드 최적화만으로
항상 100점이 된다고 약속하지 않는다.
